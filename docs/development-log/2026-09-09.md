## 09.09.2026 — ручное создание и полноценное редактирование заказов HUB

**Статус:** APPLIED / BACKEND  
**Подсистема:** HUB / orders / customers / order items / authz

Что изменено:

- добавлен серверный сценарий ручного создания заказа сотрудником HUB;
- `create_hub_manual_order(...)` умеет использовать существующего клиента либо создать клиента по имени/телефону, создать заказ и первую позицию, вычислить итоговую сумму и добавить запись `NEW` в `order_status_history`;
- добавлен `update_hub_order_details(...)` для полного редактирования заказа: клиент, бизнес-направление, источник, модель/название, комментарии и весь набор позиций;
- при редактировании сумма пересчитывается серверно по `quantity × unit_price`, позиции заменяются атомарно в рамках функции;
- обе операции ограничены ролями `ADMIN` или `MANAGER`.

Миграции:

- `20260909094826` — `hub_manual_order_creation`;
- `20260909110319` — `hub_order_editing`.

Важные технические решения:

- клиент не передаёт доверенную итоговую сумму: сервер пересчитывает её из позиций;
- количество должно быть положительным, цена не может быть отрицательной;
- business unit приводится к enum `business_unit` с явной ошибкой при некорректном значении;
- `update_hub_order_details(...)` работает как `SECURITY DEFINER`, но первым шагом проверяет `ADMIN/MANAGER`;
- `create_hub_manual_order(...)` выполнен без `SECURITY DEFINER` и также проверяет роль.

Проверка:

- `create_hub_manual_order(...)`: `anon EXECUTE=false`, `authenticated EXECUTE=true`;
- `update_hub_order_details(...)`: `anon EXECUTE=false`, `authenticated EXECUTE=true`;
- в определениях обеих функций подтверждена проверка `has_role('ADMIN') or has_role('MANAGER')`;
- `update_hub_order_details(...)` блокирует редактируемый заказ `FOR UPDATE`, проверяет клиента и валидирует каждую позицию перед записью.

Коммиты продукта: новых нет.

## 09.09.2026 — дедлайны заказов и серверные параметры напоминаний

**Статус:** APPLIED / BACKEND  
**Подсистема:** HUB / orders / deadlines / reminders / database / authz

Что изменено:

- в `orders` добавлены `due_at`, `deadline_remind_before_hours` и `deadline_note`;
- стандартное предварительное напоминание — **48 часов**;
- допустимый диапазон настройки напоминания ограничен **0–720 часов** на уровне БД;
- создан `update_hub_order_details_v2(...)`, который расширяет редактирование заказа сроком исполнения, временем предварительного напоминания и внутренней заметкой по дедлайну;
- сервер продолжает пересчитывать сумму и полностью валидировать позиции так же, как предыдущая версия RPC.

Миграция:

- `20260909145624` — `order_deadlines_and_reminders`.

Важные технические решения:

- срок хранится как `timestamptz`, чтобы не привязывать бизнес-логику к часовому поясу браузера;
- ограничение `orders_deadline_remind_before_hours_check` защищает диапазон независимо от UI;
- новая версия RPC сохраняет обратную совместимость: старая `update_hub_order_details(...)` не удалена.

Проверка:

- production-таблица `orders` содержит `due_at timestamptz`, `deadline_remind_before_hours integer DEFAULT 48`, `deadline_note text`;
- constraint подтверждает диапазон `deadline_remind_before_hours >= 0 AND <= 720`;
- `update_hub_order_details_v2(...)`: `anon EXECUTE=false`, `authenticated EXECUTE=true`, внутри подтверждена проверка `ADMIN/MANAGER`.

Коммиты продукта: новых нет.
